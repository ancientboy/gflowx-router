# gflowx-router — 订阅档位与场景对齐设计

> 目标：用户 **只理解「我订了哪一档、多久一续、有多少量」**；调用时 **只传场景标签**（`code`、`smart`…），由 **分组权益 + 场景池 + 计量** 共同决定实际路由与成本。  
> 原则：**周期只跟「会员档位」走**；场景是 **档位内的用法与池策略**，不为每个场景单独设计订阅周期（见下文「反模式」）。

---

## 1. 设计原则（摘要）

| 原则 | 说明 |
|------|------|
| **单时间轴** | 对外续费、到期、提醒只围绕 **1～2 个档位 SKU**（如月付 / 年付），不搞「每场景各一套日历」。 |
| **档位 = 分组 + 额度 + 能力边界** | 付费后进入对应 **用户分组**；额度与可选 **周期重置** 用 new-api `SubscriptionPlan` / 分组策略承载。 |
| **场景 = 调用语义** | `model` 写场景名；**池内多模型与降级** 在网关（`gflowxscene`）完成；不同档位的差异通过 **池配置或分组可用模型** 体现。 |
| **成本差异靠计量** | 不同上游倍率不同，用 **token/额度折算** 消化差异，而不是用「`smart` 单独订阅」消化。 |

**反模式**：为 `code`、`smart` 分别卖「月订阅且不同到期日」——对账、客服与实现成本都高，且与 new-api 单计划周期模型冲突。

---

## 2. 档位总览（建议 3 档 + 可选团队扩展）

面向 **个人 / 小团队** 的默认三档；团队版可再拆「席位数」或单独询价（此处只定产品语义）。

| 内部 ID | 对客名称 | 周期 SKU | 典型用户 | 核心承诺 |
|---------|----------|----------|----------|----------|
| `tier_free` | 体验版 | 无订阅 / 注册即得 | 试用、自托管管理员分发 | 低额度；场景标签可用但 **池偏小或为共享默认池** |
| `tier_pro` | 专业版 | **月付 / 年付** 二选一 | 个人开发者、小工作室 | 足额额度；**完整场景池**；优先队列（若日后实现） |
| `tier_team` | 团队版 | **月付 / 年付** + 席位数（可选） | 多人共享额度、要发票/管控 | 更高总额度或 **池隔离**（运维配置）；管理协作（可走 new-api 用户体系） |

> **说明**：「体验版」可不做收款，仅分组 `default` 或 `free`；专业版 / 团队版对应 **付费订阅计划**，支付成功后 **`upgrade_group`** 写入下表分组。

---

## 3. 与 new-api 对象的映射（实施时对照）

| 对客档位 | 建议 `upgrade_group` | `SubscriptionPlan` 要点 | 额度策略（示例，可调） |
|----------|----------------------|---------------------------|-------------------------|
| 体验版 | `free`（或默认分组） | 可不建计划，由管理员手动分组 | 低 `total_amount` 或仅每日赠送；`quota_reset_period` 可按日/周 |
| 专业版 | `pro` | 月/年各一条计划；`duration_unit` + `duration_value` | 中高 `total_amount`；`quota_reset_period`: `month` 与「按月订阅」对齐时可设 **never** 由计划周期自然续费加量，或 **month** 做「每月刷新包含量」二选一（运营定稿） |
| 团队版 | `team` | 同上；可加多条计划区分席位数 | 更高 `total_amount` 或按席倍增 |

**Stripe / Creem / 易支付**：各档位计划绑定对应 `stripe_price_id` / `creem_product_id` / 易支付金额（与 new-api 现有一致）。

## 4. 场景与池策略（按档位差异化，**不**按场景设周期）

### 4.1 用户侧（API 心智）

- 所有档位：**同一套场景标签名**（`code`、`smart`、`fast`、`cheap`、`write`、`creative`、`vision`、`translate` 等与 `docs/API.md` 一致），避免「免费版换一个标签名」。
- 差异体现在：**解析出的上游模型列表、池深度、是否允许某高成本场景**（见下表）。

### 4.2 运维 / 网关配置（当前与演进）

| 维度 | 体验版 | 专业版 | 团队版 |
|------|--------|--------|--------|
| **场景池 JSON** | 单文件全局：`pools.free.json` 或共用 `pools.default.json` 中偏短列表 | `pools.pro.json` 更长列表 / 更强模型 | `pools.team.json` 或与 pro 同池但 **分组可用模型** 更宽 |
| **分组与渠道** | `free` 分组仅绑定低价/限速渠道 | `pro` 绑定全量或主站渠道 | `team` 可独立渠道或更高并发 |
| **高成本场景 `vision`** | 可关闭（分组无视觉模型）或池仅 1 个便宜模型 | 默认可用 | 默认可用 + 更大池 |
| **别名** | 可与专业版共用或收紧 `GFLOWX_ALIASES_FILE` | 全量内置 + 自定义文件 | 同左或单独文件 |

> **演进（可选）**：在 `gflowxscene` 中支持 **按用户 `group` 选择不同池配置**（推荐 **单 JSON 文件内 `poolsByGroup`**，见 **[`GFLOWX_POOL_BY_GROUP_DESIGN.md`](GFLOWX_POOL_BY_GROUP_DESIGN.md)**），实现「同标签、不同档不同池」而仍 **单计费周期**。备选为多环境变量路径（如 `GFLOWX_SCENE_POOLS_FILE_PRO`），运维成本更高。

### 4.3 与 9router 思路的对齐

- **用户**：只选档位（订阅）+ 调用时只写场景（不传长模型名）。  
- **系统**：档位决定 **边界与预算**；场景池决定 **多模型尝试顺序**；relay 里 **失败换池中下一个**（已实现方向见 `docs/ROUTER.md`）。

## 5. 产品文案与售卖信息（对外可照抄改）

| 档位 | 一句话卖点 | 周期与价格占位 |
|------|------------|----------------|
| 体验版 | 「先传 `code` / `smart` 用起来，额度够用再升级」 | 免费或 ¥0；额度写具体数字 |
| 专业版 | 「一档搞定日常开发写作；月付灵活、年付更省」 | 月付 X / 年付 Y（8 折示例） |
| 团队版 | 「多人共享额度 + 更强池与渠道；可开票/可管控」 | 月付 / 年付 + N 席位 |

**续费提醒**：只针对 **订阅订单到期**（与 `SubscriptionPlan` 周期一致），不针对「某场景」。

---

## 6. 加购与升级路径

| 动作 | 设计 |
|------|------|
| **升级** | `free` → `pro` → `team`：新计划支付成功 → `upgrade_group` 变更；**池切换**随分组次日生效或立即生效（运维约定）。 |
| **降级** | 到期未续费 → 回退到 `free` 或只读；**池**随分组回退。 |
| **加油包（可选）** | 单次购买 **额度包**，有效期 90 天或当周期末清零；**不**单独卖「`translate` 月订阅」。 |

## 7. 验收清单（产品 / 研发）

- [ ] 后台已配置至少 **2 条** 付费 `SubscriptionPlan`（月 / 年），且 `upgrade_group` 与上表一致。  
- [ ] 各分组在 new-api 中 **渠道 / 可用模型** 与档位承诺一致。  
- [ ] 网关侧 **池文件**（或分 group 池）与档位表一致；文档写明由谁更新 JSON。  
- [ ] 控制台（default Web `/gflowx-scenes` 或独立 `frontend/`）展示：**当前分组 + 到期时间 + 剩余额度 + 场景列表（若已接只读池 API）**。  
- [ ] 用户用 **同一套场景标签** 在体验版与专业版各测一次，确认解析模型符合池配置。
